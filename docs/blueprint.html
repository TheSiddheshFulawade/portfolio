01 · Positioning

In banking, fast is expected. Correct under concurrency is the job.

Interviewers at JPMorgan, Goldman Sachs, Morgan Stanley, Barclays, Deutsche Bank, Citi or UBS technology centres rarely ask how fast something was. They ask what happens when a message is delivered twice, when the ledger call times out halfway, or when two threads debit the same account. Your resume already holds those stories: RTGS settlement, ISO 20022, Kafka and IBM MQ, a Resilience Service, thread-safe processing. The site's job is to prove them in 30 seconds for a recruiter and in 30 minutes for an interviewer.

So the design thesis is an observability console for a payment engine, applied to a career. Numbers set in monospace, system states shown as status pills, message flows instead of decorative gradients, and one working demo that runs real concurrent settlement in Java and shows its invariants holding.

Employer work is experience. Your own work is the showcase.e-Kuber 3.0 (RTGS, NEFT, settlement) appears as experience at the level of your resume: in the hero line, the metrics and the experience timeline. It is never presented as "my project", and the site has no system diagrams, code, screenshots or internal names from it. The flagship project is Settlement Lab, an open-source settlement engine you write from scratch, inspired by the domain. Interviewers can read every line of it. The judgment you built at work shows up in pattern articles that use general industry knowledge, not system specifics.
Recruiter · 30 s

Role, domain, years, location, notice period, resume PDF and LinkedIn are all visible without scrolling. Hero metrics are taken straight from the resume.

Hiring manager · 5 min

Settlement Lab's write-up (Context, Constraints, Decisions, Trade-offs, Results) and pattern articles drawn from payments work. ADR-style decision cards show judgment, which is what "senior" actually means.

Interviewer · 30 min

Settlement Lab running live, a public repo with specs, ADRs, tests and CI, and a "How this site is built" page that shows disciplined, AI-assisted engineering that you own.

Settlement Lab: your flagship open-source project

This is the centrepiece and the strongest interview conversation starter. It is your own project, in its own public repo (and embedded in the site at /lab), written from scratch on textbook patterns. It must not copy e-Kuber design, naming or code. Because you own it completely, you can walk an interviewer through any file.

  • Ledger of 1,000 in-memory accounts. Transfers lock both accounts in ascending id order, which prevents deadlock. An alternative mode uses optimistic CAS so visitors can compare the two.
  • Thread model switch: a fixed platform-thread pool or virtual threads. A blocking "GL call" of 5–40 ms shows why virtual threads win on I/O-bound work.
  • Simulated MQ as a bounded queue. Backpressure is visible as queue depth, and producers block when the queue is full.
  • Idempotency: every pacs.008-style message carries a UETR-like key. Duplicate delivery is injected on purpose and the duplicate count must stay at zero.
  • Resilience4j circuit breaker, retry with jitter, and bulkhead around the fake GL. Breaker state is streamed live.
  • Invariant checker: the sum of all balances is constant, no transfer is posted twice, and no balance goes negative. Shown as green checks, the punchline of the demo.
  • Abuse controls: Turnstile, at most 5 runs per IP per hour (Bucket4j), a global semaphore of 2 concurrent runs, hard caps on txns and workers, and a 20 s run timeout.

05 · UI screens

A payments console, applied to a career

Dark-first graphite with a light theme, settlement teal for healthy states, amber for in-flight and warnings. IBM Plex Sans Condensed for headings, Plex Sans for text, Plex Mono for every number. Motion is limited to message flow and live data, and it switches off under reduced-motion. These are direction mockups; spec 002 turns them into tokens and components.

Motion and visuals (part of spec 002)

  • Hero: a live message-flow line where payment packets travel from pacs.008 to settlement, and metrics count up once on load
  • Page changes: View Transitions API, so cards morph into their detail pages instead of hard cuts
  • Scroll: sections settle into place with a short 8 px rise; content is never hidden while waiting
  • Background: a faint dot grid that drifts slowly, drawn on canvas, paused when off screen
  • Micro-interactions: magnetic buttons, card hover glow following the cursor, a command palette that springs open
  • Settlement Lab: real-time charts and a flowing ledger, the one place motion is dense

Rules that keep it clean

  • One accent colour, one display face, generous spacing; motion explains something or it doesn't ship
  • Only transform and opacity are animated, so animations stay at 60 fps on mid-range phones
  • Native CSS and Web Animations API; no heavy animation library (budget: JS ≤120 KB)
  • Everything calms down under "reduce motion" settings
  • Before coding, the screens are refined as high-fidelity designs you approve, so you iterate on visuals cheaply

09 · Security

Treat the portfolio like a bank would treat a public endpoint

Targets: Mozilla Observatory A+, securityheaders.com A+, SSL Labs A+, zero high or critical CVEs at release.

Edge and browser

  • Strict hash-based CSP (Angular autoCsp), frame-ancestors 'none', no unsafe-inline
  • HSTS with preload, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, COOP and CORP
  • Cloudflare WAF managed rules plus rate rules on /api/*
  • No cookies or third-party trackers, so no consent banner
  • Subresource Integrity on any external asset (aim for none)

API

  • Spring Security stateless, CORS allow-list of your own origin only
  • Jakarta Validation on every input, request size limits, strict JSON
  • Server-side Turnstile check, Bucket4j limits, global run semaphore
  • RFC 9457 errors with no stack traces; only /actuator/health public
  • Secrets in Azure Key Vault through managed identity; no personal data stored

Supply chain

  • Renovate with grouped updates; OSV-Scanner, npm audit and OWASP Dependency-Check
  • CodeQL and Semgrep (SAST); gitleaks as pre-commit hook and in CI
  • Trivy image scan, CycloneDX SBOM, cosign-signed images
  • GitHub Actions pinned by commit SHA, least-privilege GITHUB_TOKEN
  • Branch protection: PR required, signed commits, required checks

Runtime and agents

  • Distroless, non-root, read-only filesystem, dropped capabilities
  • OWASP ZAP baseline scan against staging on every release
  • /security-review (built in) plus security-auditor before each PR
  • Claude permissions deny secrets and pushes; hooks enforce it
  • Threat model (STRIDE) kept in docs/threat-model.md

12 · Session management

Context is your scarcest resource

Per-session rhythm

  • One spec task per session. Start fresh (/clear) between tasks; the SessionStart hook reloads what matters.
  • Use plan mode for anything touching more than two files. Read the plan before approving.
  • Commit after every green task so a bad turn costs one rewind (Esc Esc), not an afternoon.
  • End with /handoff: what changed, what is next, open questions.
  • Watch /context. Above about 60%, finish the task, hand off and start a new session instead of letting it compact mid-task.

Scaling up

  • Run web and api tasks in parallel sessions on separate git worktrees so they never edit the same files.
  • Send exploration and reviews to sub-agents so their file dumps stay out of the main context.
  • Keep CLAUDE.md short. Move detail into skills, which load only when needed.
  • When Claude repeats a mistake twice, fix the root: a rule in a skill, or a hook if it must never happen.
  • Use the Claude Code GitHub Action (headless) for PR review, so CI catches what a tired you would miss.
13 · Notes from the field

What will decide the interview

Employer work: experience, not project.e-Kuber is RBI critical infrastructure. On the site, say you contributed to it and show only what is already on your resume. Publish no system diagrams, code, screenshots, internal names or volumes, and no RBI or ReBIT logos (text mentions are fine). Read your employment agreement and any disclosure or social-media policy, and consider telling your manager. A bank's background check may look at exactly this. Interviewers notice discretion, and they notice its absence even more.
Let Settlement Lab carry the technical proof.When an interviewer asks "show me something you built", open the Settlement Lab repo, not a description of your employer's system. Talk about work experience as decisions and lessons ("we had to guarantee exactly-once posting, so…") without describing the system itself.
Be ready for the arithmetic.100,000 transactions per hour is about 28 per second. A sharp interviewer will work that out. Frame it with what each transaction involved (ISO 20022 parsing, validation, GL posting, an MQ hop, exactly-once guarantees) and use the Lab to show you understand where throughput actually goes. Use international number format on the site; global recruiters misread "1,00,000".
Own every line."Built 100% with Claude Code" is a strength in 2026 only if you can explain any file on request. Treat agents like strong junior engineers: you approve specs, you review every PR, and you can defend each ADR.
Seniority comes from trade-offs, not adjectives.With 2+ years, don't call yourself senior. Show it through decision records, failure handling and what you would change. Keep the ML projects, but move them below the payments work so your positioning stays clear.
